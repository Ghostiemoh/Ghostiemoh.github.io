## 2024-11-20 - Optimize Font Loading in Vite Projects
**Learning:** Using `@import` inside a CSS file (like `index.css`) for loading external fonts in a Vite/React project creates a serial request chain. The browser must first download and parse the CSS before it can initiate the font download. This blocks rendering and negatively impacts First Contentful Paint (FCP).
**Action:** Always define external font requests (e.g., Google Fonts) using `<link rel="stylesheet">` tags, along with `<link rel="preconnect">` for the font domain, directly in `index.html`. This allows the browser to discover and download the fonts in parallel with other assets.
## 2024-05-25 - Avoid React State for High-Frequency Animations
**Learning:** Using `setInterval` and React state (`useState`) to drive high-frequency animations (like a number counter updating every 16ms) triggers excessive component re-renders. This blocks the main thread, increases CPU usage unnecessarily, and negatively impacts overall frame rates and interaction latency.
**Action:** Always prefer CSS transitions/animations or dedicated animation libraries (like Framer Motion's `useSpring` and `useTransform` hooked directly to a `motion` component) for values that change rapidly. These approaches bypass the React reconciliation cycle entirely, relying on the GPU or optimized direct DOM updates instead. When using `useSpring` with an explicit duration, specify the duration in seconds, not milliseconds. When rendering a `MotionValue`, it must be the sole child of the `motion` component; perform any string concatenation (like appending suffixes) inside the `useTransform` map function.
